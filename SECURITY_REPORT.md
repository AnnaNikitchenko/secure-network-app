# Звіт з безпеки

## Реалізований захист

- TLS 1.2+ із клієнтською перевіркою довіреного локального CA та SAN/hostname. Сертифікат сервера має окремий приватний ключ; приватний ключ CA після підписання не зберігається.
- SQLite з bcrypt-хешами, USER/ADMIN ролями та серверною перевіркою адміністративних операцій.
- JWT HS256 із ключем із `.env` (мінімум 32 байти), строком дії, обов'язковими claims та відкликанням через SQLite.
- MFA TOTP із challenge до видачі access JWT та одноразовим використанням кроку OTP.
- Налаштовуване тимчасове блокування login; події безпеки записуються у JSONL без паролів, токенів, OTP чи приватних ключів.
- Відкритий TCP вимкнений за замовчуванням і дозволяє тільки демонстраційні PING/ECHO.

## Результати, надані для Kali Linux

Користувач повідомив результати запуску до цієї зміни залежностей на Kali Linux із Python 3.14.7: `pytest` — 10 passed, 0 failed; Bandit — 0 issues для 614 рядків; TLS Windows–Kali та основні сценарії реєстрації, входу, передачі даних, виходу й авторизації перевірені вручну; MFA-тести пройшли.

У цій зміні нижні межі піднято до `cryptography 50.0.2` і `pytest 9.2.0`. Новий запуск на Kali після оновлення ще не виконано в межах цього сеансу; команди повторної перевірки наведено в `TESTING.md`. GitHub Actions workflow перевіряє Python 3.14 на Ubuntu і Windows, але потребує push/pull request для фактичного запуску.

Перевірки після змін у цьому Windows робочому середовищі: `pip check` успішний; Bandit — 0 проблем на 613 рядках production-коду; вибрані 4 не-TLS тести пройшли, зокрема новий тест довжини ключа без `InsecureKeyLengthWarning`. Повний `pytest` показав 5 passed, 6 failed: усі шість помилок TLS-тестів виникли на handshake з `unable to get local issuer certificate` від локального TLS inspection. `security_checks.py` також завершився помилкою цього посередника. Тести не пропускаються. `pip-audit` не зміг зв'язатися з PyPI через перевірку сертифіката; свіжого локального звіту вразливостей немає.

## Обмеження середовища розробки

Локальний Windows інтерфейс має TLS inspection, який підміняє loopback-сертифікат. Інтеграційні тести лишені без `skip` і без вимкнення валідації, тому в такому оточенні вони покажуть помилку сертифіката. Проводьте повний TLS-набір на Kali/CI вузлі без локального TLS-посередника.

Порівняльний benchmark треба запускати на Kali цією командою:

```bash
python benchmark.py --output benchmark-results --sizes 1024,65536,1048576 --repeats 5
```

Вона створить CSV, JSON і Markdown із вимірами TCP та TLS лише після успішної TLS-перевірки; жодні значення не підставляються чи вигадуються.

## Межі реалізації

- Rate limiting зберігається у пам'яті процесу, тому багатопроцесне розгортання потребуватиме спільного сховища.
- CA створено для лабораторної роботи; у робочій системі потрібна керована PKI та процедура ротації.
- Мережна реєстрація створює лише USER. ADMIN додається локально довіреною командою.
